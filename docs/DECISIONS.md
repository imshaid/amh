# Decisions

One short entry per non-obvious choice: date, decision, why.

- 2026-10-19 — Fresh codebase and fresh Supabase project; legacy app stays live until cutover and serves only as a design/PDF reference.
- 2026-10-19 — Old package list and legacy history are not migrated; the system starts clean. The new list (`docs/reference/packages-new.xlsx`) is imported through the Packages screen.
- 2026-10-19 — Package names are the WV codes (e.g. `Lunch Basic-07`) so bills match POs; item lines follow the style in BLUEPRINT §2.
- 2026-10-19 — Git: branch per segment, Conventional Commits after each working unit, push every commit, merge + tag per segment.
- 2026-10-19 — Deduction at source is a per-client rate, default 16%, until the VAT/AIT split is verified.
- 2026-10-19 — Voice input is out of scope for now. The AI assistant is available to all three admins.
- 2026-10-19 — Project files moved from `amh-v2/` to the repository root and the older root `BLUEPRINT.md` removed: Claude Code loads `CLAUDE.md` only from where a session starts, and one blueprint avoids following stale rules.
- 2026-10-19 — npm workspaces: the SPA is `apps/web`; the PDF service and shared packages (e.g. document templates used by both the preview and the PDF renderer) join as further workspaces. npm, not pnpm, because it ships with Node.
- 2026-10-19 — TypeScript 6.0, not 7: typescript-eslint supports TypeScript < 6.1 only. Revisit when it supports 7.
- 2026-10-19 — ESLint 10 with `eslint-plugin-jsx-a11y-x`: ESLint 9 is out of support and `eslint-plugin-jsx-a11y` does not support ESLint 10.
- 2026-10-19 — Hard-coded UI text is a lint error: JSX text plus `aria-label`, `title`, `alt`, `placeholder` and `label` attributes must come from translations.
- 2026-10-19 — TanStack Router file routes with automatic code splitting. Signed-in screens live under a pathless `_app` layout; sign-in and delivery links will sit outside it. New order is `/new`, so the Orders menu item can match order pages without also matching it.
- 2026-10-19 — Bangla is the default regardless of browser language. Language and theme are stored per device for now (`amh:language`, `amh:theme`) and move to the user profile in Segment 2.
- 2026-10-19 — Theme follows the device unless the user picks light or dark. `public/theme-boot.js` applies the saved choice before first paint; it is an external file so the CSP can stay `script-src 'self'`.
- 2026-10-19 — Numbers use South Asian grouping in both languages (`bn-BD`, `en-IN`: ১,১১,৮৮০ / 1,11,880), as the prototype does. Money is formatted from exact decimal strings with a ৳ prefix and a true minus sign; the UI never calculates it.
- 2026-10-19 — Only allowlisted `VITE_` variables may reach the bundle (`src/lib/client-env-policy.ts`). The build fails on any other, and on a secret or service-role key passed as the publishable key; this must happen at build time because Vite has already inlined the value by run time. A post-build scan also checks `dist/` for secret formats and for build-time secret environment values.
- 2026-10-19 — The app starts without a backend configured and says the server is not set up yet, so UI work and previews do not depend on Supabase.
- 2026-10-19 — Local Supabase uses ports 544xx (API 54421, DB 54422, Studio 54423, Mailpit 54424) so it can run beside another local Supabase project; analytics is off to save memory.
- 2026-10-19 — PWA updates wait for the user (prompt mode) so nobody loses half-typed work; installed apps check hourly. Only the app shell is precached; Supabase responses are never cached by the service worker.
- 2026-10-19 — App icon follows the hotel's logo (white serif AMH in a blue oval), set in Tinos Bold as outlines and rendered by `apps/web/scripts/generate-icons.mjs` with Playwright's Chromium, so no image library is needed.
- 2026-10-19 — Cloudflare Pages deploys come from GitHub Actions (`wrangler pages deploy`), not Cloudflare's Git integration, so nothing deploys unless the checks pass. The Pages project's production branch is `production`, so every push, main included, is a preview until launch (Segment 14).
- 2026-10-19 — The build writes `_headers`: a CSP that allows only the app and the configured Supabase origin, standard hardening headers, and `noindex` on every deployment.
- 2026-10-19 — E2E smoke tests run against a production build made with `--mode e2e`, which reads no `.env` files and goes to `dist-e2e/`, so the tests never depend on a backend and never replace the deployable `dist/`.
- 2026-10-19 — Test fixtures never use real-format keys, not even the CLI's well-known local ones; GitHub push protection rejects them.
- 2026-10-19 — The GitHub repository is public during development by the owner's choice and will be made private when the project is finished. Do not flag it as a problem.
- 2026-10-19 — Hosted Supabase project `amh` (ref `bdzgidmoaigeubsowcpo`) in ap-southeast-1 (Singapore), the owner's choice and the same region as their other project. The repo is linked to it. The database password is kept outside the repository at `~/.config/amh/supabase-db-password`; the public URL and publishable key are GitHub repository variables.
- 2026-10-19 — Segment 0 was closed before the first preview deploy: the owner left the choice to Claude, and only the owner can create the Cloudflare API token. The pipeline is verified locally with `wrangler pages dev` and deploys automatically on the first push after the token and account ID are added.
- 2026-10-20 — UI primitives are written in-house on Radix (the `radix-ui` package), shadcn-style but without its CLI, so every part follows our tokens. Class names are merged by `cn()` (clsx + tailwind-merge, taught our scale names).
- 2026-10-20 — Icons: Lucide stroke icons at 1.75px, re-exported from `src/ui/icons.ts` under the names of what they mean (`IconBilled`, `IconDelivery`); components never import `lucide-react` directly.
- 2026-10-20 — Fonts are self-hosted from Fontsource packages through our own `@font-face` rules: Bengali and Latin subsets only, woff2 only, with unicode-range. Anek Bangla uses the weight-and-width file (448 KB for Bengali) because BLUEPRINT §7 asks for the width axis; figures use 92% width. Fonts are cached by the service worker on first use, not precached, which saves about 1.5 MB at install.
- 2026-10-20 — Colour tokens were tuned for WCAG AA and are guarded by `tokens.test.ts`: muted text #748197 → #5c6981 (3.5 → 4.7:1), a new `turmeric-ink` for text on turmeric, and a separate 3:1 `field-line` for form-control edges (card and divider lines stay light). Light and dark keep the prototype's values otherwise.
- 2026-10-20 — Chart colours: the 8-slot categorical order from the dataviz method, validated on our own surfaces in both themes. Scatter-like charts (all pairs on screen) use at most 3 slots; light aqua, yellow and magenta are under 3:1, so charts using them need visible labels or a table.
- 2026-10-20 — Type scale 12/13/14/15/17/20/24/30/36 px with role utilities (`type-hero`, `type-title`, `type-heading`, `type-figure`, …). Nothing smaller than 12px, because Bangla needs more size than Latin.
- 2026-10-20 — Motion: Motion's `m` components under `LazyMotion` (strict) with `reducedMotion="user"`. Its features load with the app, not lazily: every screen's entry animation needs them, and a lazy load kept the first screen invisible for a network round trip. Radix overlays animate with CSS keyframes on `data-state`. Interface motion is 120–320 ms; data animations (counting figures, meters, sparklines) take 700 ms so the change can be followed (the prototype used 900 ms).
- 2026-10-20 — The live indicator pulses once when the connection comes up, instead of the prototype's endless pulse: BLUEPRINT §7 rules out looping decoration.
- 2026-10-20 — The sidebar shows from 1024px (Tailwind `lg`); below that the bottom bar does. The prototype switched at 960px; tablets in portrait get the phone layout with its bigger targets.
- 2026-10-20 — The theme control is a menu (same as device, light, dark) rather than the prototype's light/dark toggle, so following the device stays a real choice.
- 2026-10-20 — Language buttons show "বাং" and "EN" but are named "বাং (বাংলা)" and "EN (English)", so the visible text is part of the accessible name (WCAG 2.5.3).
- 2026-10-20 — Field text uses the `text-input` size: 15px, but at least 16px on touch screens, where iOS zooms into smaller text. A field can still ask for a bigger size.
- 2026-10-20 — DataTable is TanStack Table v9. Numbers sort biggest first. Phones get cards: one view is rendered, chosen by a media query. Rows are not clickable as a whole, so put a link in the title cell. Height-limited tables virtualise from 60 rows and are focusable regions so keyboards can scroll them.
- 2026-10-20 — Toasts are Radix Toast plus a small store usable outside React. A job toast (PDF batches) stays open until its progress reaches the total; at most three toasts are open at once.
- 2026-10-20 — Order statuses each have a tone, an icon and words. Partly paid shares billed's warning tone and differs by icon and words; cancelled is neutral.
- 2026-10-20 — The command bar uses cmdk with our own matching: every typed word must appear in the item's name or keywords; both languages' names are keywords; Bangla and Latin digits match each other. Fuzzy scoring is unreliable on Bangla's combining marks.
- 2026-10-20 — `/dev/gallery` ships in every build, unlinked from the menu but reachable from the command bar and the dashboard, so the owner can review it on a preview. Revisit at launch (Segment 14).
- 2026-10-20 — End-to-end tests run axe-core (WCAG 2.1 A and AA) on the dashboard and the gallery in light and dark, at desktop and phone sizes.
- 2026-10-20 — Segment 2 started before the owner reviewed Segment 1's look, at the owner's choice ("start Segment 2, review later"); the review stays open in PROGRESS.
- 2026-10-20 — Bill numbers have their own gap-free sequence by issue date and take the issue date's fiscal year (`AMH/27-28/B-0001`); a revision keeps its bill's number with `-R1`, `-R2`. Owner's choice; legacy bills left ক্রমিক blank, so there was no habit to keep.
- 2026-10-20 — Members sign in with their phone number and a 6-digit PIN (owner's choice of length) through the `member-auth` Edge Function. The function peppers the PIN (HMAC-SHA256 with `AUTH_PIN_PEPPER`) and the database keeps bcrypt of that; on success it signs the member in to Supabase Auth with a password derived from the same pepper and the user id, which nobody types and which cannot be guessed through Auth's own endpoint. Auth's built-in password hooks for lockouts need a paid plan; this works on any.
- 2026-10-20 — Five wrong PINs lock a phone number for 15 minutes, the next five for 30, doubling to a day; a run of mistakes is forgotten after a day; a PIN reset by another member lifts the lock. Unknown numbers are counted and answered exactly like members' numbers, so nothing reveals who is a member. Wrong-PIN answers say how many tries are left, because the people using it are not technical.
- 2026-10-20 — Members are Supabase Auth users with a synthetic email (`<id>@members.amh.invalid`); `.invalid` can never receive mail. Sign-ups are off in Auth; the email provider must stay on because the derived-password sign-in uses it.
- 2026-10-20 — The operator (a caller holding the project's secret key) adds the first members with `npm run members`; later a member can add others (Settings, Segment 14) through the same function actions. Switching a member off deactivates the profile (RLS shows them nothing at once) and bans their Auth user so sessions stop refreshing.
- 2026-10-20 — "Stay signed in on this device" is the default: the session lives in localStorage until sign-out. Unticked, it lives in sessionStorage and ends with the tab. Sign-out is for this device only (`scope: local`).
- 2026-10-20 — Language and theme are saved on the member's profile and applied when they sign in on any device; signed out, the device keeps its own choice.
- 2026-10-20 — Without a backend configured, the app opens without sign-in as a UI preview (no data exists to protect); the end-to-end smoke tests and local UI work rely on it. Real access control is RLS, not the route guard.
- 2026-10-20 — Database internals live in a `private` schema the Data API never serves. Default privileges are revoked, so new tables and functions are closed until a migration grants them; members often get column-level grants so numbers, states and frozen totals are written only by triggers and server functions. `00_security.test.sql` fails if any table lacks RLS or a policy, if anon can touch anything, or if a new public function is executable by members without being added to its approved list.
- 2026-10-20 — Invariants are enforced by triggers, whoever writes (app, AI, service role): issued-means-locked, one bill per order, write-once issued documents, immutable numbers, the order status rules. App-recognisable errors use SQLSTATE codes `AMH01`–`AMH04`.
- 2026-10-20 — Deduction is computed as `round(gross × rate, 2)` and expected net as `gross − deduction` (not the other way round), so a future split into VAT and AIT can round each part like the client does. Bills check the frozen figures agree.
- 2026-10-20 — Challan numbers come from the same locked sequence table as order and bill numbers (scope `challan`, keyed by order id), not a counter column on `orders`, so numbering a challan never touches the order row or its audit trail.
- 2026-10-20 — Every order has its bill row from the moment it is created (revision 0, draft), with the client's billing name and address as its header.
- 2026-10-20 — Payments recorded against a bill count for its later revisions too: settlement is computed over all of an order's bills. A billed order's status follows its allocations (billed, partially paid, paid).
- 2026-10-20 — One audit trigger per business table writes `audit_log` with actor, channel (from `amh.channel`, else ui/system), batch id (`amh.batch_id`, for AI undo) and the order the change belongs to. The log is append-only even for the service role. Personal preferences, bookkeeping columns and an issued document's payload are left out.
- 2026-10-20 — Realtime publishes only `audit_log`: every business change lands there with its table, row and order, so one subscription per device is enough to refetch and highlight.
- 2026-10-20 — The Data API returns `numeric` as JSON numbers; screens that show money select it as text (`gross::text`) so the exact decimal string reaches the formatter.
- 2026-10-20 — Order statuses in the UI are the database enum's values (`partially_paid`, not `partlyPaid`); `src/ui/order-status.ts` takes them from the generated types.
- 2026-10-20 — Edge Functions use web APIs only and no dependencies (plain `fetch` to Auth and the Data API), so their logic is unit-tested in Node with Vitest and type-checked with the rest of the repository; a lint rule keeps Node imports out of function code.
- 2026-10-20 — Database checks that need Supabase running are a separate command, `npm run check:stack` (pgTAP, plpgsql lint, generated-types check, integration tests, end-to-end sign-in against a `stack` build), and a separate CI job; `npm run check` still needs no Docker. Previews deploy only when both pass.
